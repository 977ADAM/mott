# AGENTS.md — брифинг для ИИ-агента, работающего в репозитории Mott

Этот файл — точка входа для любого AI-агента (и для человека, который впервые открыл
репозиторий). Он короткий и операционный. **Глубокие детали — в `SPEC.md`, он источник
истины по решениям.**

---

## 1. Что это за проект

**Mott** (с чеченского — «язык») — дообучение мультиязычной `Qwen3-4B` на чеченских
данных, чтобы получить инструктивную модель, говорящую на чеченском естественно и грамотно.

| | |
|---|---|
| Базовая модель | `mlx-community/Qwen3-4B-4bit` (36 слоёв, 4 бита, group_size 64) |
| Метод | QLoRA через `mlx-lm` (LoRA на замороженной квантованной базе) |
| Железо | MacBook Pro M5, 24 ГБ объединённой памяти |
| **Бюджет под тензоры** | **17,76 ГБ** (`max_recommended_working_set_size`) — не 24 ГБ! |
| Язык | чеченский (`ce`), низкоресурсный |
| Команда | один разработчик — носитель чеченского |

### Языковые правила общения

- **Отвечать по-русски.**
- Быть конкретным: код, команды, форматы. Без общих слов.
- **Если чего-то не знаешь точно — сказать прямо, не выдумывать.** Чеченский
  низкоресурсный, и выдуманная «лингвистика» тут дороже ошибки в коде.
- Весь чеченский текст в датасетах **финализирует носитель**. Агент не сочиняет
  чеченский как эталон.

## 2. Быстрые команды

```shell
uv sync                                    # поставить окружение (Python 3.13 + mlx-lm)
uv run python scripts/download_data.py     # скачать датасеты NM-development в data/raw/
uv run python scripts/check_tokens.py      # замер токенизации ce/ru/en + проверка шаблона
uv run mlx_lm.lora --help                  # все флаги обучения
```

Обучение (проверенный конфиг; почему именно батч 2 — см. грабли №11):

```shell
uv run mlx_lm.lora \
  --model mlx-community/Qwen3-4B-4bit --train --data ./data \
  --batch-size 2 --num-layers 16 --learning-rate 1e-5 --iters 1800 \
  --max-seq-length 512 --mask-prompt --seed 42 \
  --steps-per-eval 150 --steps-per-report 50 --save-every 300 \
  --adapter-path ./adapters/mott-v0.1
```

`--iters 1800` = 3 эпохи по 1 197 примеров при батче 2. Пересчёт: `итераций = 3 × N / batch`.

Оценка и генерация:

```shell
uv run mlx_lm.lora --model mlx-community/Qwen3-4B-4bit \
  --adapter-path ./adapters/mott-v0.1 --data ./data --test

uv run mlx_lm.generate --model mlx-community/Qwen3-4B-4bit \
  --adapter-path ./adapters/mott-v0.1 --prompt "Муха хьо?"
```

## 4. Формат данных — самый частый источник ошибок

`mlx_lm.lora --train` читает `data/train.jsonl` (обязательно), `data/valid.jsonl`
(опционально) и `data/test.jsonl` (для `--test`).

**Один JSON-объект на строку**, формат `chat`:

```jsonl
{"messages": [{"role": "user", "content": "..."}, {"role": "assistant", "content": "..."}]}
```

Обязательные ограничения:

| Правило | Почему |
|---|---|
| `<think>` в `content` писать **не надо** | шаблон Qwen3 подставляет пустой блок сам |
| в `content` **не должно быть** подстроки `</think>` | шаблон по ней режет сообщение |
| `system` обязан быть **первым** в `messages` | шаблон проверяет `messages[0]` |
| один объект на строку, без переносов внутри | парсер построчный |
| `reasoning_content` не нужен | обучаем в non-thinking режиме |

## 5. Грабли, на которые уже наступали

Список реальных ошибок этого репозитория. Не повторять.

1. **`uv_build` требует `module-root = ""`.** Пакет лежит в корне (`mott/`), а `uv_build`
   по умолчанию ищет `src/<name>/` и падает с
   `Expected a Python module at: src/mott/__init__.py`. Настройка уже стоит в
   `pyproject.toml` — не удалять. Раскладку `mott/` в корне не «чинить» на `src/`.

2. **`| tail` маскирует exit code.** `uv add ... | tail -25` вернул `exit 0` при реальном
   провале сборки. Использовать `set -o pipefail` и смотреть `${PIPESTATUS[0]}`, либо
   вообще не заворачивать в пайп.

3. **`google/wmt24pp` не содержит чеченского.** Проверены все 55 конфигов — только
   `en-XX_YY`. Чеченский WMT24++ лежит в `NM-development/wmt24pp-ce`. Не путать.

4. **`nmd-ce-ru-171k-v0` — это словарь, а не корпус.** Медиана 2 слова на строку, 40 %
   строк — одно слово, ~75 % из словаря Мациева. Скормить его в chat-формате целиком =
   получить модель, отвечающую обрывками. Брать только предложения (> 5 слов, ~26 %).

5. **Имена полей различаются между датасетами.** `ce`/`ru` у `nmd-ce-ru-171k-v0`,
   но `ce_text`/`ru_text` у `ce_ru_officials` и `ce_ru_toponyms`,
   `che_Cyrl`/`rus_Cyrl`/`eng_Latn` у `smol_ce`. Не хардкодить `ce`/`ru` без проверки.

6. **В `wmt24pp-ce` есть строка-canary** (`domain == "canary"`, `is_bad_source == True`) —
   служебная, фильтровать вместе с `is_bad_source`.

7. **Лимит памяти — 17,76 ГБ, а не 24 ГБ.** При нехватке памяти снижать в порядке:
   закрыть браузер → `--batch-size 2` → `--grad-checkpoint` → `--max-seq-length 1024` →
   `--num-layers 8`. `iogpu.wired_limit_mb` не поднимать (нужен `sudo`).

8. **Чеченский стоит 1,58× токенов против русского** (замер: `check_tokens.py`). Причина
   **не** в палочке — она кодируется одним токеном штатно. Причина в том, что **ни один**
   из 16 чеченских диграфов не является единицей словаря BPE: каждая пара букв = 2 токена.
   Итог: 3,61 токена на слово против 2,11 у русского. Эффективный контекст в словах для
   чеченского примерно вдвое меньше. Для обучения на наших данных 2048 хватает с запасом
   (p90 предложения — 25 слов), но при длинной генерации это ударит. Токенизатор не
   переучивать.

9. **Коран: артефакты — это ПРОБЕЛЫ, а не кавычки.** 64,5 % строк с двойными пробелами,
   8,7 % с пробелом перед запятой, 10,4 % перед точкой — чистится (`mott/text.py`).
   **Кавычки `"` трогать нельзя:** это настоящий знак препинания (прямая речь, названия
   мечетей), а непарные числа объясняются разбиением по аятам — речь открывается в одном
   стихе и закрывается в другом. В первой редакции этого файла стояло обратное
   утверждение («повреждение текста»), оно было **ошибочным**. Две попытки убрать пробелы
   внутри кавычек ломали законную пунктуацию (`элира: "Ас` → `элира:"Ас`), поэтому
   обработка кавычек убрана намеренно. Не возвращать без проверки носителем.

10. **Коран — шестикратно параллельный корпус, и русские редакции НЕ равноценны.**
   Каждый аят лежит в 6 вариантах: 2 чеченских перевода (Магомедов, Ибрагимов) × 3 русские
   редакции. Сравнение на аяте 2:255:
   - `Kuliev` — `Аллах - нет божества, кроме Него, Живого, Вседержителя.` (грамотный, официальный перевод смыслов)
   - `Osmanov` — чистый, но местами без точек
   - `Adel` — `Аллах - нет бога , кроме Него,  - Живой, Сущий ;` (пробелы перед запятыми, рваные тире — черновой/машинный)

   **Дедуп по `ce` «по порядку» оставлял худшую редакцию — Adel.** Теперь есть
   `edition_rank()` в `mott/sources.py`, который предпочитает Kuliev. Не убирать.

   Дедуп по `ce` схлопывает 6 вариантов в 2 и убирает ~23 000 строк — это не мусор.
   Но следствие: **94 % русских текстов имеют 2 разных чеченских перевода**, то есть
   для задачи ru→ce цель неоднозначна. Решение по этому — за носителем.

11. **Батч больше 2 роняет обучение по памяти — это НЕ очевидно.** `mlx_lm` паддит весь
   батч до **самого длинного примера в нём** (`trainer.py`), поэтому `--max-seq-length`
   не защищает: он лишь потолок. У нас разброс длин медиана 98 / max 490, и паддинг
   раздувает батч в **2,18×**. Проверено: `--batch-size 8` дал пик 17,755 ГБ и
   `RuntimeError: [METAL] Insufficient Memory` на 20-й итерации.

   Модель памяти: **~10 МБ на позицию токена**, бюджет активаций ~14 ГБ ⇒ **~1 400
   позиций**. Худший батч = `batch_size × максимальная длина`. Отсюда `--batch-size 2`.

   Ещё два неочевидных факта:
   - **Больший батч не ускоряет**: батч 2 → 1,5 примера/с, батч 8 → 1,44 примера/с.
   - **Сортировать `train.jsonl` по длине бесполезно** — тренер перемешивает батчи
     (`np.random.permutation`).

   Лечится не батчем, а отсечкой длинных: `scripts/build_dataset.py --max-tokens 512`.

## 6. Источники данных (проверено)

| Датасет | Строк | Поля | Что это |
|---|---|---|---|
| `NM-development/nmd-ce-ru-171k-v0` (default) | 171 224 | `ce`,`ru`,`source` | словарь, ~26 % предложений |
| `NM-development/nmd-ce-ru-171k-v0` (benchmark) | 360 | `ce`,`ru`,`en`,`source` | словарь + Библия |
| `NM-development/wmt24pp-ce` | 998 | `lp`,`domain`,`source`,`target`,`is_bad_source` | новости en→ce |
| `NM-development/ce_ru_officials` | 66 | `ce_text`,`ru_text`,`source` | официальные тексты |
| `NM-development/ce_ru_toponyms` | 344 | `ce_text`,`ru_text`,`source` | топонимы |
| `NM-development/smol_ce` | 825 | `che_Cyrl`,`rus_Cyrl`,`eng_Latn` | выровненный 3-язычный корпус |

**Ключевой факт: готового инструктивного корпуса на чеченском не существует.**
Во всех девяти датасетах — параллельные тексты и словарь. Датасет придётся
конструировать, а не скачивать. Целевая пропорция v0.1 (согласована):

- ~500 пар — перевод ru↔ce из предложенческой части;
- ~150–200 пар — инструкции/диалоги, написанные носителем вручную;
- 50–100 — `test.jsonl`, дедуплицированный по нормализованному `ce`.

> Перед сплитом **обязателен дедуп по `ce`**: `benchmark`-сплит может пересекаться
> с `default`, иначе тест покажет завышенный результат.

## 7. Что делать агенту

- Перед изменением поведения — свериться со `SPEC.md`; расхождения с реальностью
  (как с `wmt24pp`) фиксировать в спеке, а не молча обходить.
- Любое утверждение о внешнем мире (датасет, API, флаги) **проверять**, а не вспоминать:
  HF API и `--help` доступны и быстры.
- Помечать непроверенное явно: `[проверено]` / `[TBD]`.
- Не переучивать токенизатор и не менять базовую модель без обсуждения.
- Помнить, что рядом работает носитель языка — лингвистические решения за ним.
